# 2 — Design

Moves ideas and concepts from [[1 - Plan]] into grounded features and system requirements.

## Inputs

`Intent.md` from the Plan stage.

## Skills

[[qsdlc-design]] is the primary skill for this stage. For creative or novel asks, it calls on [[qsdlc-feature-research]] first to gather open-source examples and prior art — so requirements are grounded in what's actually been built before, not invented from nothing.

## Outputs

- **Document — `spec.md`**: features (with acceptance criteria), system requirements, an architecture sketch, open-source references, and risks. See [[Documents]].
- **Artifact — design pitch deck**: the AI's execution vision presented for review — problem recap, proposed solution, key flows, why this approach. Diagrams in it use Archify where possible; see [[Artifacts]].

## Hand-off

[[3 - Build]] reads both `Intent.md` and `spec.md`. Any pushback during the design review gets captured in `spec.md`'s decision log before this stage is considered complete — Build shouldn't have to guess what was actually agreed.
